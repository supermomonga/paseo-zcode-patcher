# セッションの使用量を公式hostから取得して既存メーターへ渡す

## Context and Problem Statement

Paseoのコンテキストメーターは使用量と上限の両方を必要とする。既存ZCode providerは会話全体の累積トークン数を使用量として渡し、上限を渡していなかった。アカウントのクオータ取得もセッションを識別しないため、接続先の異なるZCodeセッションへ正しい契約情報を対応付けられない。

## Decision Drivers

* コンテキストの現在値と累積使用量を区別すること
* 使用中の接続先だけを表示し、アカウントの取り違えを防ぐこと
* 資格情報と認証通信の所有者をZCodeに保つこと
* 既存のメーターとクオータカードを再利用すること

## Considered Options

* セッションの公式snapshotとusage-statsサービスを既存表示へ接続する
* モデル上限を固定し、累積トークン数から使用率を推測する
* PaseoがZCodeの資格情報を読み、独自にクオータAPIを呼ぶ

## Decision Outcome

採用: **セッションの公式snapshotとusage-statsサービスを既存表示へ接続する**。

コンテキストは`runtime.contextUsage.used / size`を正本とし、snapshot・モデル応答完了・圧縮・モデル変更・ターン終了時に反映する。累積usageで現在のコンテキストを上書きしない。

`provider.usage.list.request`に任意の`agentId`を追加し、サーバーが対象セッションの`getProviderUsage()`へ接続する。ZCodeは既存bridgeの`usage-stats`チャンネルに`getEntitlementSnapshot`だけを公開する。接続先は現在モデルから解決し、`requirePreferredProvider: true`と`allowEnvApiKey: false`を指定する。資格情報をPaseoへコピーしない。

対象は個人契約とする。Coding Planのpercentageは使用率0〜100、Start Planは残量比率0〜1として公式実装に合わせて変換する。未対応接続先・Team Plan・取得失敗は明示し、数値を捏造しない。取得失敗は会話から分離し、nativeエラーの詳細をクライアントへ渡さない。

クライアントのキャッシュはセッション・モデル単位、provider内部のキャッシュは接続先を識別し、有効期間は5分とする。取得中のモデル変更や遅れて返った別接続先の結果で現在表示を上書きしない。

ADR 0012までのrenderer変更範囲を、既存メーターへのagentId・modelの受け渡しと使用量queryの分離まで拡張する。専用カードや画像assetは追加せず、ADR 0008のoverlayへ必要なprotocol・client・server生成物を加える。

### Consequences

* Good, because 公式snapshotの圧縮後の減少と再開時の値をそのまま利用できる。
* Good, because 認証の所有境界を保ち、別接続先への代替を防げる。
* Good, because 共通UIを利用し、ZCode専用の画面を増やさない。
* Bad, because 固定ZCodeの非公開サービスに依存し、更新時に応答形式の再検証が必要になる。
* Bad, because セッション指定をprotocol・client・server・rendererへ通すためoverlay対象が増える。

### Confirmation

対象テストで割合変換、初期値、圧縮、累積値との分離、キャッシュ、接続先切替、遅延応答、失敗時の情報非公開を確認する。公式hostで実測値と変換結果を照合し、生成アプリで表示を確認する。overlayは固定commitのクリーンなソースから再生成して検証する。

## More Information

Team Planは組織・プロジェクトの選択を追跡できる契約を設計する場合に別途検討する。新しいprovider APIや対応ZCodeバージョンへ移行する際は、この取得・変換経路を再検証する。
